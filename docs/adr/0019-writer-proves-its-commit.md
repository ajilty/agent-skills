# The writer proves its commit; verification runs against the committed state, not the working tree

Field report: an Implementer reported `DONE` with a commit SHA, but had validated its
**working tree** (visible tests green) while leaving the substantive fixes **uncommitted**
and committing only an intermediate. Trusting the report would have carried a broken commit
into irreversible state surgery; the integrator caught it only by manually peeking at
`git show`. This is a repeatable failure mode: "validated" is asserted against the working
tree, not the artifact that actually ships (the commit).

The pre-existing contract permitted it. `implementer.md` said "run visible tests **before
you commit**" and defined `DONE` as "built, visible tests pass, tags resolved" — none of
which requires the commit to *contain* the fixes or the worktree to be clean. `verifier.md`
step 1 ran the held-out suite without stating **which tree/ref** it ran against, so a
Verifier operating on a dirty worktree would validate uncommitted work too — the same
blindspot, one layer down. `ledger.sh done` is fail-closed on a Verifier verdict but knows
nothing about git state.

**Decision.** Make the artifact (the commit), not the working tree, the thing that is
proven — at two layers:

- **The writer proves it (implementer.md).** `DONE` now requires a clean commit: after
  committing, confirm `git status --porcelain` is empty and `git show --stat HEAD` contains
  the task's changes, and **report the SHA + that file list** so the integrator reads the
  proof instead of re-deriving it. Visible tests must pass against the committed HEAD, not
  an unsaved tree. A green working tree with fixes left uncommitted is not `DONE`.
- **The Verifier independently confirms it (verifier.md), deterministically.** A new
  outcome-mode step 0 runs `worktree.sh committed <ticket> implementer` before any test:
  exit 0 = clean tree with the work committed (proceed, testing that committed state); exit
  2 = uncommitted changes; exit 5 = nothing committed → `REJECTED(uncommitted-work)`. The
  check is a new read-only `worktree.sh` subcommand reusing its existing clean/ahead logic,
  so the guarantee is a scripted, unit-tested check, not model prose alone. (It resolves on
  PATH via the ADR-0018 `bin/` shim.)

## Considered options
- **Prose-only implementer instruction** — rejected as the sole fix: the field failure was
  a model self-reporting "done" against the wrong surface; a second prose bullet it can
  skip is not a guarantee. Keep the implementer contract (it makes the proof cheap to read)
  but back it with the Verifier's scripted check.
- **Enforce worktree-clean inside `ledger.sh done`** — rejected: `ledger.sh` is pure
  board/coreutils state; teaching it to resolve worktrees and shell git couples the ledger
  to git state and duplicates `worktree.sh`. The Verifier is the right owner (independent
  confirmation), and `worktree.sh` already owns git.
- **A PreToolUse hook that blocks a dirty done** — rejected as disproportionate: no hook
  event cleanly straddles the DONE transition with the writer's worktree in scope, and the
  Verifier step 0 already gives deterministic teeth with a clear reject route.
- **Verifier just re-derives from `git show`** — rejected by the field lesson itself: don't
  make the integrator re-derive; make the writer prove and the Verifier confirm with one
  scripted check.

## Consequences
- `worktree.sh committed <ticket> <persona>` added (exit 0 committed&clean / 2 uncommitted /
  5 nothing-committed / 4 missing), covered by `tests/test_worktree.sh`.
- `implementer.md` and `verifier.md` bodies change, so `agents/implementer.md` and
  `agents/verifier.md` are regenerated by `build.sh` (committed==fresh-build drift guard);
  the Codex/opencode installers read the same bodies, so they inherit the contract.
- An uncommitted-work ship is now caught by an independent, scripted check with a named
  reject reason, instead of relying on an integrator's manual `git show` peek.
- Does not address resume redundancy (a clean board pushing all resume state into prose):
  tracked separately as a board-schema hardening.
